# MVS-G5 probe E10: Programmed Symbols (2026-10-08) - CLOSED, NEGATIVE (capability limit)
Probe: src/probe/PACFSA.asm (generated by tools/gen_probe_e10.py) + src/probe/PACG5P.cob + CLIST G5PROBE, deck `G5P`
(job PACG5P01). Completely separate from PACMAN: no game source, copybook, CLIST or load module was touched.
Purpose: establish the host-defined-symbol ceiling of the target environment TK4-/MVS 3.8J + TSO + c3270 4.5ga6, not to
force Programmed Symbols (PS) to work.

## Result
**Programmed Symbols are not supported in the validated TK4-/MVS 3.8J + TSO + c3270 environment. G4 is the production
character-set ceiling.** This is a capability limit of the terminal, established by a live probe plus the terminal's
own capability reply and source. It is not an implementation failure of the probe or of the game.

## What E10 sends (in order)
1. Read Partition Query (`F3 0005 01 FF 02`, TPUT NOEDIT); reply read whole by TGET ASIS.
2. Screen 1 (TPUT FULLSCR, WCC C3 restores the keyboard locked by the reply); the user presses ENTER (this first AID
   also clears the TSO NOEDIT hold after a Query Reply, D28, so step 3 is not held).
3. One Load Programmed Symbols field, TPUT NOEDIT, 32 bytes:
   `F3 001F 06 00 C1 C1 01` + 24 bytes = one 9 x 12 Pac-Man symbol (12 rows x 2 bytes, 9 dots left-justified).
   WSF, L=31, SF ID X'06', FLAGS 00, LCID C1, CHAR C1, TYPE 01. Field layout = our reading of IBM GA23-0059
   (non-extended form), not verifiable without a PS device; irrelevant for c3270, which rejects the field by its ID
   after checking only its length (x3270 Common/sf.c).
4. Inbound window: TGET ASIS,NOWAIT every 0.5 s, up to 3 s; the first input ends it.
5. Screen 2: bytes C1-C8 under A) SA X'43' X'C1' (the set just loaded), B) base set, C) SA X'43' X'F1' (APL, positive
   control proven in E9). ENTER ends, PA2 redraws.
6. Line mode restored (STTMPMD OFF, STFSMODE OFF, STLINENO LINE=1): READY returned normally.

## Live run (user, c3270 4.5ga6 `-trace -scriptport 4001`, 2026-10-08 20:03-20:06)
Final line: `G5P RC=0012 QLEN=0180 SCRNS=0002 AID=7D LOADRC=0000 ILEN=0053`.
Trace window (probe only, logon excluded): docs/evidence/g5-c3270-e10-window.txt.

Conclusions from A/B/C: A = B means set C1 was not loaded (the terminal falls back to the base set); C differs from B,
so character-set selection itself works: the limit is specific to Programmed Symbols.

### Reading the result fields correctly
- `LOADRC=0000` is the return code of the host TPUT NOEDIT that carried the Load PS: TSO/VTAM accepted the OUTBOUND send.
  It is NOT a terminal acceptance of Load PS (a 3270 terminal does not answer a WSF in plain TN3270; see check 3).
- `ILEN=0053` is NOT a terminal response to Load PS. Exact cause: screen 1 is unformatted, so ENTER on it sends AID +
  cursor + all screen text: the trace shows a 311-byte record at 20:04:18.517 = 309 bytes of 3270 data + IAC EOR.
  The probe's key TGET (GETKEY, 256-byte buffer) received the first 256 bytes; TSO kept the remaining 309 - 256 = 53
  bytes queued, and the first TGET NOWAIT of the inbound window returned them at once. They decode (CP037) to
  `SULT SCREEN.PRESS ENTER TO SEND LOAD PS. PA2 = REDRAW`, the tail of screen 1's own text (the record was sent BEFORE
  the Load PS, 6 ms earlier). Side effect: the inbound window ended at its first poll (screen 2 arrived 1 ms after the
  Load PS); the c3270 trace covers the full 94 s after the load with no inbound, so check 3 does not depend on the
  window. Probe slip, harmless (same family as E9's `RC=0012`); E10 is not rebuilt.
- `RC=0012` is the last TGET (ENTER on screen 2, also unformatted, larger than 256 bytes): input truncated, as in E9.
- `QLEN=0180`, `SCRNS=0002`, `AID=7D`: reply read, two screens sent, ended with ENTER.

## Consequences
- G5 closed as a capability limit: "Not supported in the validated c3270 environment; G4 renderer is the production
  fallback and graphics ceiling for host character sets."
- G6 (multicolour / triple-plane PS) depends on PS: BLOCKED / NOT APPLICABLE in this environment, reason inherited from G5.
  No G6 implementation is built around an unsupported feature.
- A PS-capable physical terminal or emulator could be investigated in a separate, future compatibility branch (E10 is
  reusable there: same deck, run under that emulator). Not required to close G5 and not pursued now; the project does not
  install or depend on Vista TN3270, PCOMM or similar.
- Next meaningful visual improvement for the real environment: the scaled renderer (preferably 2 x 2), not more PS work.
