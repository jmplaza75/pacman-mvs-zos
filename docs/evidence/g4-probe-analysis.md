## Run 1 (JOB 189 build): screen PASS, then X Wait
Order was: screen (TPUT FULLSCR) -> Read Partition Query (TPUT NOEDIT) -> reply TGET -> key TGET.
c3270 -trace: the Query Reply (inbound) is followed by `Keyboard lock ... +ENTER_INHIBIT`; nothing restored the keyboard
afterwards, so the user's ENTER was `action queued (kybdlock 0x200)` inside c3270 and never transmitted; the probe sat in
its key TGET loop (5-minute timeout). Cause: any inbound transmission, the Query Reply included, locks the 3270 keyboard
until the host writes with WCC keyboard restore.
Fix (E9 only): the game's validated order (G1-G3): query -> reply -> screen (WCC C3 restores the keyboard) -> key.
